# Real Quantization Policy Experiments

This experiment path is for real, pre-generated quantized LLM/encoder feature
pools. It is separate from the SimHash reuse controller on purpose: the first
question is whether a graph-semantic score can choose node precision better
than a degree-only proxy.

## Required Feature Pools

Prepare three tensors with identical shape `[num_nodes, emb_dim]`:

```text
cache_data/{dataset}_{model}_oracle_FP16.pt
cache_data/{dataset}_{model}_oracle_INT8.pt
cache_data/{dataset}_{model}_oracle_INT4.pt
```

For example:

```text
cache_data/cora_llama2_7b_oracle_FP16.pt
cache_data/cora_llama2_7b_oracle_INT8.pt
cache_data/cora_llama2_7b_oracle_INT4.pt
```

These files should be generated by actually running the encoder/LLM under the
target precision. The runner does not fake-quantize embeddings in this mode.

You can generate a first bitsandbytes-backed set with:

```bash
python -m GraphhopSimhash.generate_real_quant_pools \
  --datasets cora pubmed \
  --llm_name llama2_7b \
  --configs fp16 int8 int4 \
  --batch_size 4
```

This writes:

```text
cache_data/{dataset}_llama2_7b_oracle_FP16.pt
cache_data/{dataset}_llama2_7b_oracle_INT8.pt
cache_data/{dataset}_llama2_7b_oracle_INT4.pt
```

The generated `INT8` pool uses bitsandbytes 8-bit loading, and `INT4` uses
bitsandbytes NF4 4-bit loading. This is a real quantized model execution path,
but it is not the same thing as an official AWQ/GPTQ calibration-and-packed
kernel pipeline.

Recommended first implementation:

```text
FP16: full-precision encoder/LLM embedding
INT8: real INT8 model, e.g. W8A8/SmoothQuant or bitsandbytes INT8
INT4: real INT4 model, e.g. AWQ/GPTQ W4A16
```

If you only have the older local pools from `generate_qllm_features.py`, use:

```bash
--real_quant_fp_tag W4A16 \
--real_quant_int8_tag W4A8 \
--real_quant_int4_tag W4A4
```

Those older pools are useful for plumbing/debugging, but they should be
described carefully because they are not the same as an official AWQ/GPTQ
kernel-backed deployment.

## Graph-Aware Calibration For W/A Stress Tests

`generate_qllm_features.py` now supports graph-aware calibration. Instead of
calibrating on the first 32 text nodes, it can select calibration nodes from the
graph using degree or TSER:

```text
prefix           first N nodes, legacy behavior
random           random N nodes
degree           top-N high-degree nodes
tser             top-N TSER-risk nodes
tser_stratified  high TSER + graph-context-risk + low-degree-unique + mid/random
```

The fake W/A quantizer uses a lightweight SmoothQuant/AWQ-style scaling search:

```text
choose scale s from calibration activations
runtime path: Q(X / s) @ Q(W * s)
```

The calibration grid now uses the target W/A bit width and evaluates the same
activation-aware path used at inference. This matters for W4A8 and W4A4; if the
calibration is run at 16/16, the scale search is effectively degenerate.

Generate graph-aware W4A pools with separate output tags:

```bash
python generate_qllm_features.py \
  --datasets cora \
  --config W4A8 \
  --calibration_strategy tser_stratified \
  --calibration_size 256 \
  --tag_suffix TSER256

python generate_qllm_features.py \
  --datasets cora \
  --config W4A4 \
  --calibration_strategy tser_stratified \
  --calibration_size 256 \
  --tag_suffix TSER256
```

For the more faithful SmoothQuant-style INT8 baseline, start with W8A8:

```bash
python generate_qllm_features.py \
  --datasets cora \
  --config W8A8 \
  --calibration_strategy random \
  --calibration_size 256 \
  --smooth_alpha 0.5 \
  --tag_suffix RAND256_SQ
```

This keeps the calibration set neutral while testing whether W8A8 embeddings
remain close enough to FP16 to be useful. Evaluate it as the INT8 pool:

```bash
python -m GraphhopSimhash \
  --datasets cora \
  --runs 3 \
  --experiment_suite real_quant_ablation \
  --real_quant_model_name llama2_7b \
  --real_quant_fp_tag FP16 \
  --real_quant_int8_tag W8A8_RAND256_SQ \
  --real_quant_int4_tag INT4 \
  --real_quant_error_norm 1.0 \
  --real_quant_fp_ratio 0.90 \
  --real_quant_int8_ratio 0.10
```

For a calibration ablation, generate random and degree-calibrated pools too:

```bash
python generate_qllm_features.py --datasets cora --config W4A8 \
  --calibration_strategy random --calibration_size 256 --tag_suffix RAND256
python generate_qllm_features.py --datasets cora --config W4A4 \
  --calibration_strategy random --calibration_size 256 --tag_suffix RAND256

python generate_qllm_features.py --datasets cora --config W4A8 \
  --calibration_strategy degree --calibration_size 256 --tag_suffix DEG256
python generate_qllm_features.py --datasets cora --config W4A4 \
  --calibration_strategy degree --calibration_size 256 --tag_suffix DEG256
```

Then evaluate graph-aware mixed precision execution on those pools:

```bash
python -m GraphhopSimhash \
  --datasets cora \
  --runs 3 \
  --experiment_suite real_quant_ablation \
  --real_quant_model_name llama2_7b \
  --real_quant_fp_tag FP16 \
  --real_quant_int8_tag W4A8_TSER256 \
  --real_quant_int4_tag W4A4_TSER256 \
  --real_quant_error_norm 1.0 \
  --real_quant_fp_ratio 0.85 \
  --real_quant_int8_ratio 0.10
```

The cleanest paper-style comparisons are:

```text
Calibration ablation:
  RAND256 vs DEG256 vs TSER256

Execution ablation at the same generated pools:
  DegreeTopK    vs TSERTopK
  DegreeCascade vs TSERCascade
```

This separates two claims:

```text
1. Graph-aware calibration makes the quantized pools less harmful.
2. Graph-aware mixed precision chooses better nodes to protect at the same budget.
```

## Policy

The runner trains the GNN on the FP pool, then evaluates multiple feature
assignments under the same trained GNN:

```text
AllFP
AllINT8
AllINT4
DegreeTopK
TSERTopK
DegreeCascade
TSERCascade
DegreeRiskThreshold
TSERRiskThreshold
```

For mixed policies, every node gets a sensitivity score:

```text
TSER(v) =
  3 * PropagationRisk_q
  + 2 * GraphContextRisk_q
  + 2 * LowDegreeUniqueRisk_q
```

The real quantization error is measured from the actual pools:

```text
Error_INT8(v) = 1 - cos(E_FP(v), E_INT8(v))
Error_INT4(v) = 1 - cos(E_FP(v), E_INT4(v))
```

Errors are quantized to `[0, 15]` using `--real_quant_error_norm`.

The mixed precision decision is:

```text
if TSER(v) * Error_INT4_q(v) <= --real_quant_int4_threshold:
    use INT4
elif TSER(v) * Error_INT8_q(v) <= --real_quant_int8_threshold:
    use INT8
else:
    use FP16
```

The most interpretable baselines are fixed-budget ranking policies:

```text
DegreeTopK:
  top --real_quant_fp_ratio degree-risk nodes use FP
  remaining nodes use --real_quant_tail_precision

TSERTopK:
  top --real_quant_fp_ratio TSER-risk nodes use FP
  remaining nodes use --real_quant_tail_precision

DegreeCascade:
  top FP ratio by degree-risk use FP
  next --real_quant_int8_ratio by degree-risk use INT8
  tail nodes use INT4

TSERCascade:
  same FP/INT8/INT4 ratios, but ranked by TSER
```

These pairs have identical precision budgets. The only difference is which
nodes are protected, so they directly test whether TSER selects more important
nodes than degree.

`DegreeRiskThreshold` and `TSERRiskThreshold` are deployment-style policies
using the real quantization error thresholds described above.

## Run

True real-quant experiment:

```bash
python -m GraphhopSimhash \
  --datasets cora pubmed \
  --runs 3 \
  --experiment_suite real_quant_ablation \
  --real_quant_model_name llama2_7b \
  --real_quant_fp_tag FP16 \
  --real_quant_int8_tag INT8 \
  --real_quant_int4_tag INT4 \
  --real_quant_fp_ratio 0.10 \
  --real_quant_int8_ratio 0.20
```

With older W4A pools:

```bash
python -m GraphhopSimhash \
  --datasets cora \
  --runs 1 \
  --experiment_suite real_quant_ablation \
  --real_quant_model_name llama2_7b \
  --real_quant_fp_tag W4A16 \
  --real_quant_int8_tag W4A8 \
  --real_quant_int4_tag W4A4
```

Useful sweeps:

```bash
--real_quant_error_space raw
--real_quant_error_space encoded
--real_quant_error_norm 0.10
--real_quant_error_norm 0.20
--real_quant_int4_threshold 80
--real_quant_int4_threshold 120
--real_quant_int8_threshold 60
--real_quant_int8_threshold 100
--real_quant_fp_ratio 0.10
--real_quant_fp_ratio 0.20
--real_quant_int8_ratio 0.20
--real_quant_tail_precision int4
--real_quant_tail_precision int8
```

## Metrics

The final table reports:

```text
I4 %     fraction of nodes using INT4 features
I8 %     fraction of nodes using INT8 features
FP %     fraction of protected/full precision nodes
Cost     simple relative cost proxy: FP=1.0, INT8=0.5, INT4=0.25
Acc      downstream GNN test accuracy
Drop %   baseline FP accuracy minus this policy accuracy
AvgErr   average selected feature cosine error
```

The main comparison is:

```text
DegreeTopK vs TSERTopK
DegreeCascade vs TSERCascade
```

At the same precision budget, TSER should ideally have lower accuracy drop than
the degree-only policy. The threshold policies are useful after this, when
tuning a deployment cost-accuracy point.
